# 稳定性试验 · 文件登记与撤销门禁

药品稳定性试验的原始测量数据一旦有误，建模组不能再拿到由它派生的清洗表与批次汇总。本应用把“文件登记”和“依赖撤销”做成一个不可篡改的登记簿：

- 上传**原始测量 / 清洗表 / 批次汇总** CSV。后两类必须登记其派生的**准确父文件 ID**。
- 文件 ID、父项、原始文件名、摘要、登记时间**一经登记不可修改**；父项必须在提交时已登记且未撤销。
- 质控员撤销任一文件后，**直接或间接依赖它的所有文件立即停止下载**（HTTP 410），页面列出受影响链。
- 修复件使用**新 ID**；旧派生件不会因为新文件出现而恢复。
- 上传与撤销并发时不会发布引用已撤销父项的文件；写盘或登记失败不暴露半成品；重启后资格不变。

## 快速启动（Docker Compose）

```bash
docker compose up --build
```

浏览器打开 <http://localhost:8000>。

- 数据（SQLite 数据库 + 原始字节）保存在命名卷 `registry-data`，容器重建不丢。
- 健康检查：<http://localhost:8000/healthz>。
- 若要在共享环境使用，请修改 `docker-compose.yml` 中的 `SECRET_KEY`（只用于 flash/session 签名）。

### 不使用 Docker 的本地运行

```bash
python3 -m pip install -r requirements.txt
python3 wsgi.py            # 开发服务器，监听 127.0.0.1:8000
# 或
gunicorn --bind 0.0.0.0:8000 --workers 1 --threads 8 wsgi:app
```

环境变量：`DATABASE_PATH`、`STORAGE_DIR`、`MAX_UPLOAD_BYTES`（默认 20 MiB）、`SECRET_KEY`、`HOST`、`PORT`。
未设置时数据落在仓库内 `data/`（已被 `.gitignore` 忽略）。

## 浏览器操作流程

1. **登记原始测量**：文件 ID 如 `RAW-2024-0116-A`，类型选“原始测量”，父文件留空，选择 `samples/raw-batch-2024-0116.csv` 上传。
2. **登记清洗表**：文件 ID `CLEAN-2024-0116-A`，父文件填 `RAW-2024-0116-A`，上传 `samples/cleaned-batch-2024-0116.csv`。
3. **登记批次汇总**：文件 ID `SUM-2024-0116-A`，父文件填 `CLEAN-2024-0116-A`，上传 `samples/summary-batch-2024-0116.csv`。
4. 在文件详情页填写质控员姓名，点击“撤销此文件”。确认后清单与详情页立即显示各下游“已停止下载”，受影响链按层级列出；对这些文件点下载会得到 410 阻断页，其中显示阻断路径。
5. 修复：用新的 ID（如 `RAW-2024-0116-A-FIX`、`CLEAN-2024-0116-A-FIX`）重新登记；旧派生件仍保持停止下载。

`samples/` 下附有三份可直接上传的示例 CSV。

## 允许的依赖类型

| 文件类型 | 父项 |
|---|---|
| 原始测量 `raw` | 无（提交时填写父项会被拒绝） |
| 清洗表 `cleaned` | 必须是 `raw` |
| 批次汇总 `summary` | 必须是 `cleaned` 或上一层 `summary`（便于汇总修订链） |

类型不匹配、父项不存在、父项已撤销都会被拒绝，且不会留下任何可下载文件。

## 设计要点

### 不可修改的登记

`files` 表通过 CHECK 约束保证 raw 无父项、派生件必有父项；通过触发器保证：

- 只允许一次从“在册”到“已撤销”的状态迁移；
- ID、类型、原始文件名、存储名、SHA-256、大小、父项、登记时间均不可更新；
- 行不可删除；撤销不可撤销；`revoked_by` 不可覆盖。

`events` 表是只追加的审计日志（register / revoke），与状态变更在同一事务内写入，UPDATE/DELETE 被触发器拒绝。

### 原子登记：不会暴露半成品

1. 上传流被分块写入 `storage/.tmp/` 下的私有临时文件，边写边算 SHA-256、检查大小与二进制内容、解析 CSV。
2. 取 SQLite `BEGIN IMMEDIATE` 写锁后**重新校验父项及其整条上游是否可用**，再以 `link(2)` 把载荷发布到 `storage/files/<id>`（目标已存在则失败，绝不覆盖），并在同一事务插入登记行与审计事件。
3. 任何失败都回滚事务并删除刚发布的载荷；若 `COMMIT` 已持久化后才报错，则保留载荷（删除会让一次已成功的登记变成坏下载）。进程在发布与提交之间崩溃只会留下**没有登记行的孤儿文件**，它不可见、不可下载，启动扫描会在同一把锁下清理。
4. 临时文件在 `finally` 中删除；启动扫描只清理超过 1 小时的临时文件，避免误删另一进程仍在流式写入的上传。重复使用同一 ID 的重试会先回收该 ID 的孤儿载荷。

上传与撤销的竞态由同一把写锁串行化：要么撤销先提交（新上传因 `parent_revoked` 被拒），要么上传先提交（随后撤销使该子文件一并停止下载）。测试用 25 轮双线程竞态并核对审计事件顺序验证这一点。

### 下载资格是实时推导的

不缓存“可下载”状态。每次下载都沿 `parent_id` 向上遍历，任一祖先已撤销（或无法解析，fail-closed）即返回 410；磁盘载荷缺失或被截断（大小与登记不符）同样返回 410。因此重启、页面停留、多进程都不会让已撤销文件“复活”。

另有一条更严的登记规则：父项必须“在当前可用”，即其自身也不能被更上游的撤销所阻断；否则新子文件一出生就是不可下载的。

### 已知边界

- 采用单 gunicorn worker + 8 线程：SQLite 写入已在进程内串行，且避免启动清理与另一个 worker 的在途发布竞态。若要多进程横向扩展，跨进程写入仍由 `BEGIN IMMEDIATE` 保证正确，但请在部署时确保启动清理只运行一次或接受其“仅清理无登记行载荷”的语义（它绝不会删除已登记文件）。
- 没有身份认证与角色系统：质控员姓名是自由文本（会记入审计）。如需真实权限控制，应在反向代理或后续版本接入认证。
- 撤销是逻辑标记，不删除原始字节，便于审计与追溯；因此磁盘占用不会因撤销而下降。
- 未提供按文件 ID 搜索/分页；清单一次性渲染，适合单实验室规模的数据量。
